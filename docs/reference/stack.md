## Принцип
Андрій може відмовитися від CRM. Тому сайт має бути основою: об'єкти, фото, ліди й клієнти живуть у Supabase/R2. CRM — це зовнішнє джерело й канал на портали, а не сховище.

## Потоки даних
- Об'єкти: Plektan → синк по cron (`after_date`) → Supabase + фото в R2 → сайт.
- Ліди: форма / ШІ → Supabase (першими) → Plektan `addAdvert` → Telegram менеджеру.
- Без CRM: об'єкти через адмінку → Supabase/R2. Зникає лише публікація на портали.
- Джерело правди для об'єктів у кожен момент одне: CRM або адмінка. Інакше будуть дублі.

## Plektan API — головне
- `search` (пагінація ≤20), `view`, `addAdvert`, `getContactPersons`/`getPublicInfo`, `getDistricts`/`getSubway`.
- Неактуальні не віддає, тому синк ховає зниклі. `is_mls` фільтруємо. Координат немає — геокодування. Ціни текстом — парсинг. Фото копіюємо в R2.
- Партнерська кнопка на кожній сторінці. LUN не підтримується.
- Оголошення власників, які Plektan збирає з порталів, — це ліди для ріелторів. На сайт їх не виводимо.
- Деталі — в [plektan-api.md](plektan-api.md).

## Адмінка (+$300, етап 1)
- Список лідів.
- CRUD об'єктів + фото в R2 (найдовша частина).
- SEO: title/description; для об'єктів генерація за шаблоном з ручним перевизначенням; поля для статичних сторінок.
- Автоматично: sitemap, schema.org, canonical. Без аналізу ключових слів.

## ШІ-асистент (+$700–900, етап 1, функціонал погодити)
- Чат на сайті: уточнює район, тип, кімнати, бюджет, оплату (готівка/іпотека), терміни, контакт.
- Шукає лише по об'єктах з бази, дає посилання. FAQ агентства з тексту клієнта.
- Структурований лід → Supabase + Plektan + Telegram.
- Згода на обробку ПД, Turnstile, ліміт витрат.

## Можливий функціонал (етап 2+, незалежний від CRM)
Функції, які в CRM є «з коробки», варто мати на боці сайту на випадок відмови від Plektan.

| Функція | Як | Оцінка |
|---|---|---|
| Обране без логіну | localStorage, працює на одному пристрої | входить в етап 1 |
| Вхід клієнтів через Telegram / Google | Supabase Auth + Telegram Login Widget з дозволом боту писати | ~$150–250 |
| Збережені пошуки + сповіщення в Telegram (email як резерв) | cron порівнює нові об'єкти із запитами в Supabase → Telegram Bot API | ~$150–250, +$100–150 за Telegram |
| Зниження ціни на об'єкти з обраного | той самий механізм сповіщень | у межах попереднього |
| Telegram-бот з ШІ-асистентом | той самий бот, що для входу й сповіщень | окремо |
| XML-фід на портали (LUN, далі — інші) | генерація з Supabase | +$200–300 за LUN, інші оцінити |
| Простий облік лідів у адмінці (статус, відповідальний, нотатки) | замінник воронки CRM | оцінити |

- Альтернатива для збережених пошуків — Plektan `addAdvert` (купівля) + `autosends` (email/Viber). Це без своїх акаунтів, але зникне разом із CRM.
- Обмеження Telegram: писати можна лише тим, хто увійшов і дав дозвіл, номера телефону для цього недостатньо. У кожному повідомленні має бути кнопка «відписатися».
- Логін потрібен лише для цих функцій. Звичайним відвідувачам сайту реєстрація не потрібна.

## Безпека даних
- Акаунти (Supabase, Cloudflare, домен) оформлюються на клієнта, у розробника доступ.
- RLS у Supabase: публічно доступні лише опубліковані об'єкти; ліди тільки для адмінки (у перспективі — свої дані для залогіненого клієнта).
- Адмінка за логіном, ключі лише на сервері, HTTPS.
- Бекапи: Supabase Pro робить щоденні копії, що зберігаються 7 днів (ковзне вікно); R2 вони не покривають. Опційно: щотижневий `pg_dump` у R2 через GitHub Actions.

## Гарантія
- Помилки розробки виправляються безкоштовно, без терміну давності. Критичні — за 1–2 дні.
- Не є помилкою: зміни в API CRM, ШІ чи хостингу, чужі правки коду, нові функції.

## Відкриті питання
- Чи віддає `search` лише робочу базу агентства? Уточнити в Plektan або на тестовому акаунті.
- Старий WordPress-сайт: чи переносити об'єкти, хто це робить.
- Функціонал ШІ — погодити з Андрієм.
